IS 237 · Topic 6

Review Questions

Try each question before opening the suggested answer.

1. Why is growth rate more useful than a single runtime measurement?
Suggested answer: Growth rate shows how work changes as input size increases and is less dependent on one machine, language or moment.
2. What does n normally represent in algorithm analysis?
Suggested answer: The size of the input, such as the number of array elements or records.
3. What is time complexity?
Suggested answer: A description of how the amount of computational work grows with input size.
4. What is space complexity?
Suggested answer: A description of how additional memory use grows with input size.
5. Why is 3n + 5 classified as O(n)?
Suggested answer: The linear term dominates for large n; constants and lower-order terms are ignored asymptotically.
6. What is Big-O used for?
Suggested answer: An asymptotic upper bound, commonly used in introductory analysis to communicate worst-case growth.
7. What is Θ notation?
Suggested answer: A tight asymptotic bound when an algorithm is bounded above and below by the same growth order.
8. List the common growth classes from smaller to larger growth.
Suggested answer: O(1), O(log n), O(n), O(n log n), O(n²), O(2^n), O(n!).
9. What is the best case of linear search?
Suggested answer: The target is at the first checked position, requiring O(1) work.
10. What is the worst case of linear search?
Suggested answer: The target is last or absent, requiring O(n) comparisons.
11. What precondition does binary search require?
Suggested answer: The data must be sorted, and efficient indexed access is highly desirable.
12. Why is binary search O(log n)?
Suggested answer: Each comparison discards roughly half of the remaining search interval.
13. Why is binary search less attractive on a linked list?
Suggested answer: Finding the middle node is not O(1) because traversal is needed.
14. What does sorting accomplish?
Suggested answer: It rearranges values according to an ordering relation, enabling ranking, easier search and grouped processing.
15. What does it mean for a sorting algorithm to be stable?
Suggested answer: Equal-key records preserve their original relative order.
16. What does in-place mean?
Suggested answer: The algorithm uses only a small amount of extra storage beyond the input.
17. Describe bubble sort's core strategy.
Suggested answer: Repeatedly compare adjacent elements and swap out-of-order pairs.
18. When can optimised bubble sort achieve O(n)?
Suggested answer: When the data is already sorted and an early-exit swapped flag is used.
19. Describe selection sort's core strategy.
Suggested answer: Find the minimum remaining value and place it at the next sorted position.
20. Why is selection sort O(n²) even on sorted input?
Suggested answer: It still scans the unsorted remainder to find the minimum on each pass.
21. What practical advantage can selection sort have?
Suggested answer: It performs relatively few swaps.
22. Describe insertion sort's core strategy.
Suggested answer: Grow a sorted prefix by inserting each new value into its proper position.
23. Why can insertion sort be effective on nearly sorted data?
Suggested answer: Few shifts are required, giving near-linear behaviour in favourable cases.
24. What is the main idea of merge sort?
Suggested answer: Divide into halves, recursively sort them, then merge the sorted halves.
25. Why is merge sort O(n log n)?
Suggested answer: There are about log n levels and O(n) merging work per level.
26. What extra memory does standard array merge sort use?
Suggested answer: O(n) temporary storage.
27. What is the main idea of quicksort?
Suggested answer: Partition values around a pivot, then recursively sort the left and right partitions.
28. What is the average time complexity of quicksort?
Suggested answer: O(n log n).
29. What is the worst-case time complexity of quicksort?
Suggested answer: O(n²), typically when partitions are repeatedly very unbalanced.
30. Why can quicksort outperform selection sort at scale?
Suggested answer: Balanced partitioning reduces recursive depth to about log n instead of repeatedly scanning nearly the whole unsorted region.
31. Why can a stable sort matter for records?
Suggested answer: It preserves previous ordering among records with equal current keys.
32. Give one reason to prefer iteration over recursive sorting code in some contexts.
Suggested answer: To reduce call-stack usage or because the platform/runtime handles iteration more predictably.
33. Give one situation where insertion sort may be preferable.
Suggested answer: Small or nearly sorted inputs.
34. Give one situation where merge sort may be preferable.
Suggested answer: When guaranteed O(n log n) and stability matter and extra memory is acceptable.
35. What does algorithm optimisation mean at this level?
Suggested answer: Improving the algorithmic strategy—such as avoiding repeated work or choosing better structures—before micro-level code tuning.
