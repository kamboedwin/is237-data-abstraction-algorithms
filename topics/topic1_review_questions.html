IS 237 · Topic 1

Review Questions

Try each question before opening the suggested answer.

1. Why should problem solving begin before programming?
Suggested answer: Because coding is only an implementation step. The solver must first understand the required result, inputs, constraints and assumptions so the programme solves the correct problem.
2. Define an algorithm in your own words.
Suggested answer: A finite and well-defined sequence of steps for solving a class of problems or performing a computation.
3. Distinguish an algorithm from a programme.
Suggested answer: An algorithm describes the logic independently of a programming language; a programme implements that logic using the syntax and facilities of a particular language.
4. State six useful characteristics of an algorithm.
Suggested answer: For example: unambiguous steps, defined inputs, defined outputs, finite termination, feasible/effective steps, language independence and correctness.
5. Why is finiteness important?
Suggested answer: An algorithm must terminate after a finite number of steps rather than continue indefinitely for a valid input.
6. Name five common operations performed on data structures.
Suggested answer: Examples include traversal, searching, sorting, insertion, update, deletion and merging.
7. Why can the frequency of operations influence data-structure choice?
Suggested answer: Different structures make different operations cheaper or more expensive, so the dominant operations should influence representation choice.
8. What is problem decomposition?
Suggested answer: Breaking a large problem into smaller, manageable subproblems that can be designed, verified and combined.
9. Why is pseudocode useful?
Suggested answer: It expresses algorithmic logic clearly while avoiding syntax details of a specific programming language.
10. What is a specification?
Suggested answer: A description of what a procedure must accomplish, including relevant assumptions and expected results.
11. Explain the difference between verification and testing.
Suggested answer: Testing observes selected executions; verification reasons about whether the procedure satisfies its specification for the intended class of inputs.
12. Why are boundary cases important?
Suggested answer: Algorithms often fail at limits such as one element, first/last positions or minimum/maximum allowed values.
13. What is an invariant?
Suggested answer: A property that remains true at a particular point during repeated execution and can support a correctness argument.
14. Give the invariant for the maximum-finding algorithm.
Suggested answer: After each processed item, the stored maximum is the largest value among all items examined so far.
15. Describe brute-force problem solving.
Suggested answer: Use a direct or exhaustive approach; it may be simple but can become expensive as the problem grows.
16. What is the basic idea of divide and conquer?
Suggested answer: Split a problem into smaller subproblems, solve them, then combine the results.
17. Why can two correct algorithms still be meaningfully different?
Suggested answer: They may differ in time, memory, clarity, implementation complexity or suitability to the data and environment.
18. What is a priori analysis?
Suggested answer: Theoretical analysis performed before or independently of a specific implementation, focusing on operations, input size, memory and growth.
19. What is a posteriori analysis?
Suggested answer: Empirical analysis performed after implementation by measuring actual runtime, memory or other statistics on a target system.
20. Why should a priori and a posteriori analysis both be useful?
Suggested answer: Theory explains expected scaling and allows design comparison; benchmarking validates the behaviour of a particular implementation in a real environment.
21. What does input size n represent?
Suggested answer: A measure of problem size, such as the number of array elements, records, characters, vertices or edges.
22. What is a key operation in algorithm analysis?
Suggested answer: A representative operation whose repetition captures much of the computational work, such as a comparison, swap or node visit.
23. Distinguish time complexity and space complexity.
Suggested answer: Time complexity concerns growth in computational work; space complexity concerns growth in memory requirements.
24. Distinguish fixed and variable space conceptually.
Suggested answer: Fixed space does not depend on input size; variable space changes with the problem size, such as temporary arrays or recursion-stack frames.
25. Define best case, average case and worst case.
Suggested answer: Best is the minimum work for inputs of size n; worst is the maximum; average is expected work under an explicit input-distribution assumption.
26. For linear search, what inputs illustrate the best and worst cases?
Suggested answer: Best: target at the first position. Worst: target at the last position or absent, requiring n comparisons.
27. Why does average-case analysis require an assumption?
Suggested answer: Expected cost depends on how likely different inputs or target positions are; without a probability model there is no well-defined average.
28. What is asymptotic analysis?
Suggested answer: Analysis of how an algorithm's time or space grows as input size becomes large, abstracting away many machine-specific details.
29. What is the formal introductory meaning of Big-O, Big-Omega and Big-Theta?
Suggested answer: Big-O gives an asymptotic upper bound, Big-Omega a lower bound, and Big-Theta a tight bound.
30. Why should Big-O not simply be defined as 'worst case'?
Suggested answer: Worst case describes a set of input scenarios; Big-O describes an upper mathematical bound. A worst-case cost can be expressed using O, but the concepts are not synonyms.
31. Explain the statement 'Data Structure + Algorithm → Solution'.
Suggested answer: A data structure organises information while an algorithm acts on that organisation; effective solutions depend on matching both to the required operations.
32. Give one real application where algorithm design matters and explain why.
Suggested answer: Answers vary, e.g. navigation requires route-finding methods that search many possible paths efficiently while satisfying distance/time constraints.
