Review Questions

Try each question before opening the suggested answer.

1. Why should problem solving begin before programming?
Suggested answer: Because coding is only an implementation step. A solver must first understand the required result, inputs, constraints and assumptions so that the programme solves the correct problem.
2. Define an algorithm in your own words.
Suggested answer: A finite and well-defined sequence of steps for solving a class of problems or performing a computation.
3. Distinguish an algorithm from a programme.
Suggested answer: An algorithm describes the logic independently of a programming language; a programme implements that logic using the syntax and facilities of a particular language.
4. State five useful characteristics of an algorithm.
Suggested answer: For example: definite/unambiguous steps, finite termination, effective/executable steps, clearly defined inputs/outputs, and correctness/general applicability.
5. What is problem decomposition?
Suggested answer: Breaking a large problem into smaller, more manageable subproblems that can be designed, verified and combined.
6. Why is pseudocode useful?
Suggested answer: It expresses the logic of an algorithm more precisely than ordinary language while avoiding the syntax details of a specific programming language.
7. What is a specification?
Suggested answer: A description of what a procedure is required to do, often including assumptions about inputs and the expected result.
8. Explain the difference between verification and testing.
Suggested answer: Testing tries selected inputs to observe behaviour; verification reasons about whether the procedure satisfies its specification, potentially beyond the tested examples.
9. Why are boundary cases important?
Suggested answer: Algorithms frequently fail at limits such as empty/single-element inputs, first/last positions or maximum/minimum allowed values.
10. What is an invariant?
Suggested answer: A property that remains true at a particular point during repeated execution and can help explain why an algorithm is correct.
11. Give the invariant for the maximum-finding algorithm.
Suggested answer: After each processed item, the variable holding the current maximum is the largest value among all items examined so far.
12. Describe brute-force problem solving.
Suggested answer: Use a direct or exhaustive approach, often simple but potentially expensive when the problem size grows.
13. What is the basic idea of divide and conquer?
Suggested answer: Split a problem into smaller subproblems, solve them, and combine their results.
14. Why can two correct algorithms still be meaningfully different?
Suggested answer: They may use different amounts of time, memory, implementation effort or other resources.
15. What does input size n represent?
Suggested answer: A measure of problem size, such as the number of array elements, records, vertices or other relevant units.
16. What does O(n) suggest conceptually?
Suggested answer: The amount of work grows approximately in proportion to the input size.
17. Why is Big-O not the same as runtime in seconds?
Suggested answer: Seconds depend on hardware, language and implementation. Big-O focuses on how resource use grows with input size.
18. Distinguish time complexity and space complexity.
Suggested answer: Time complexity concerns growth in operations/time; space complexity concerns growth in additional memory.
19. Explain the statement 'Data Structure + Algorithm → Solution'.
Suggested answer: A data structure organises information while an algorithm acts on that organisation; the effectiveness of a solution depends on both.
20. Give one real application where algorithm design matters and explain why.
Suggested answer: Answers vary, e.g. navigation uses route-finding algorithms because the system must search many possible paths efficiently while satisfying constraints.
